# nsys-viewer

A browser-only viewer for Nsight Systems SQLite exports and PyTorch profiler traces. Open a local `.sqlite` or `.json` file to inspect GPU kernel timelines and a per-kernel runtime breakdown. The file stays in your browser; there is no upload or backend.

Compressed exports open directly: `.gz`, `.zst`, `.zip`, `.tar.gz`, and `.tar.zst` are detected from the file contents and unpacked in the browser. This makes it practical to move traces to a phone, for example:

```bash
zstd -19 trace.sqlite        # or: gzip -9 trace.sqlite / zip trace.zip trace.sqlite
```

xz, bzip2, and 7z are not supported.

### PyTorch profiler traces

Chrome-trace JSON from `torch.profiler` opens the same way, including the `*.pt.trace.json(.gz)` files written by `tensorboard_trace_handler`:

```python
with torch.profiler.profile(activities=[ProfilerActivity.CPU, ProfilerActivity.CUDA]) as prof:
    model(inputs)
prof.export_chrome_trace("trace.json")
```

GPU kernels are drawn per device and stream. Kernel details also show the kernel's launch config (grid, block, registers, shared memory, estimated occupancy) and the CPU ops that were running when it was launched (for example `## forward ## › aten::linear › aten::addmm`), matched through the CUDA runtime call's correlation ID. Enable `ProfilerActivity.CPU` to get the launching ops. The JSON is scanned event by event instead of parsed whole, so traces of several hundred MB load; on a phone, prefer compressing them.

```bash
npm ci
npm run dev
```

```bash
npm run build
npm run preview
```

## GitHub Pages

Push this repository to GitHub, then select **GitHub Actions** under
**Settings → Pages → Build and deployment → Source**. The workflow in
`.github/workflows/pages.yml` builds and deploys the site on pushes to `main`.

The Vite build uses relative asset paths, so the same build works at a project
URL such as `https://<user>.github.io/<repo>/` and when previewed locally.
`dist/` is generated by the workflow and does not need to be committed.

On phones and tablets: swipe sideways on the timeline to pan, pinch to zoom, and tap a kernel for details (the details panel stays pinned to the bottom of the screen). Turn on **Measure** in the toolbar to drag out a span; drag its edges to adjust it. Vertical swipes scroll the page as usual. Row reordering is mouse-only.

On foldables and tablets the layout adapts to each screen: the cover screen gets the phone layout; an unfolded screen keeps the full-width timeline and shows every breakdown column without sideways scrolling. Half-folded, the timeline and the details/breakdown move to opposite sides of the hinge and scroll independently — top/bottom in tabletop posture, left/right in book posture. This uses the [Viewport Segments API](https://developer.mozilla.org/en-US/docs/Web/API/Viewport_segments_API) (Chromium on Android foldables); other browsers fall back to the unfolded layout. On touch screens kernel lanes are taller and taps snap to the nearest kernel within a few pixels.

Drag device rows to reorder them, or edit their labels. Drag across the timeline to measure a span; drag its edges to adjust it. Shift+drag or scroll horizontally to pan, and pinch or use +/− to zoom. Click a kernel for details. Row order and labels are saved locally in the browser.

The browser tab title defaults to the SQLite filename. Double-click the trace heading or click **Rename** to set an alias; Enter or clicking away saves it, and Escape cancels. **Reset title** restores the filename. Aliases are saved locally per filename and file size.

Measuring a span switches the kernel breakdown to that span. **Span %** is summed kernel time inside the selection divided by its duration; concurrent launches and multiple GPUs can exceed 100%. Kernels crossing either boundary contribute only their time inside the span. Calls count launches overlapping the selection, and Avg uses their clipped durations. Hover or click a kernel to see its individual contribution alongside its full duration. Clearing the selection restores the full-trace breakdown. Device and name filters still apply; searching does not change percentage denominators.

Kernel details and the breakdown table explain what each kernel does. Tap a kernel bar, or tap a row in the breakdown, to see its category (matmul, attention, NCCL, KV cache, normalization, MoE, Triton…) and a plain-language summary. The name is also decoded where possible: dtype, GPU architecture, GEMM tile size, NCCL algorithm and protocol, and the ops fused into a torch.compile kernel. Explanations are pattern-matched from the name offline (`src/explain.ts`), so they are best-effort and unknown custom kernels are marked as unrecognized.

The breakdown groups exact kernel names. **GPU share** is summed kernel time divided by total kernel time for the selected GPUs. **Wall %** is the time covered by that kernel name divided by the full trace span. Kernel names can overlap, so Wall % does not add to 100% or represent removable latency.

The viewer reads GPU kernel activity from Nsight Systems SQLite exports and PyTorch profiler traces. CPU activity (beyond the launching op in PyTorch traces), NVTX, CUDA API calls, and memory operations are not shown. Nsight's SQLite schema may change between versions.
